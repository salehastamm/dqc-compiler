# «قطری بودن روی کیوبیت X» یعنی چه؟

> این مهم‌ترین مفهوم کل پیاده‌سازی است. تمام الگوریتم ۱ مقاله در نهایت
> به همین یک پرسش خلاصه می‌شود.

---

## ۱. از ماتریس‌های واقعی شروع کنیم

یک گیت تک‌کیوبیتی، یک ماتریس ۲×۲ است. **قطری (diagonal)** یعنی
تنها درایه‌های ناصفر روی قطر اصلی قرار دارند:

```
Z  = [ 1   0 ]      Rz(θ) = [ e^-iθ/2    0    ]      H = 1/√2 [ 1   1 ]
     [ 0  -1 ]              [   0     e^+iθ/2 ]               [ 1  -1 ]

     ✅ قطری             ✅ قطری                      ❌ قطری نیست
```

اما **معنای فیزیکی** قطری بودن چیست؟ ببینیم هر گیت با حالت‌های پایه چه می‌کند:

| گیت | `\|0⟩` تبدیل می‌شود به | `\|1⟩` تبدیل می‌شود به |
|---|---|---|
| `Z` | `\|0⟩` | `-\|1⟩` |
| `Rz` | `e^{-iθ/2}·\|0⟩` | `e^{+iθ/2}·\|1⟩` |
| `H` | `(\|0⟩+\|1⟩)/√2` | `(\|0⟩-\|1⟩)/√2` |

**یک گیت قطری هرگز عوض نمی‌کند که شما در کدام حالت پایه هستید.**
`|0⟩` همان `|0⟩` باقی می‌ماند و فقط یک عدد (فاز) جلویش ظاهر می‌شود.
اما `H` حالت `|0⟩` را به یک **ترکیب** از `|0⟩` و `|1⟩` تبدیل می‌کند —
یعنی دامنه را جابه‌جا کرده است.

> **قطری = مقدار صفر-یا-یکِ کیوبیت را حفظ می‌کند و فقط فاز اضافه می‌کند.**

---

## ۲. حالا بخش «روی کیوبیت X»

برای یک گیت دوکیوبیتی، ماتریس ۴×۴ است و پرسیدن «آیا قطری است؟» بیش از حد کلی است.
به‌جای آن، **هر بار درباره‌ی یک کیوبیت** می‌پرسیم:

> آیا این گیت، مقدار صفر-یا-یکِ **آن کیوبیت مشخص** را حفظ می‌کند؟

گیت `CX` با کنترل `c` و هدف `t` را کامل بنویسیم (ترتیب پایه `|c t⟩`):

```
|00⟩ → |00⟩        |10⟩ → |11⟩
|01⟩ → |01⟩        |11⟩ → |10⟩
```

### پرسش درباره‌ی `c`

در هر چهار سطر، آیا `c` مقدارش را حفظ می‌کند؟

`00→00` (c: ۰→۰ ✅) ، `01→01` (۰→۰ ✅) ، `10→11` (۱→۱ ✅) ، `11→10` (۱→۱ ✅)

**به `c` هرگز دست زده نمی‌شود → پس CX روی `c` قطری است.** ✅

### پرسش درباره‌ی `t`

سطر `10→11`: مقدار `t` از ۰ به ۱ تغییر کرد. **مقدار عوض شد.**

**→ پس CX روی `t` قطری نیست.** ❌

**یک گیت، دو پاسخ متفاوت.** معنای «قطری روی کیوبیت X» دقیقاً همین است.

### نمای بلوکی

اگر ماتریس ۴×۴ را بر اساس مقدار `c` بلوک‌بندی کنیم، موضوع بدیهی می‌شود:

```
        c=0        c=1
      ┌───────┬───────┐
 c=0  │  I    │   0   │   ← بلوک‌های خارج از قطر، صفر هستند
      ├───────┼───────┤     یعنی هیچ نشتی بین c=0 و c=1 نیست
 c=1  │  0    │   X   │     → روی c قطری است ✅
      └───────┴───────┘
```

اگر همان ماتریس را بر اساس مقدار `t` بلوک‌بندی کنیم، بلوک‌های خارج از قطر
**صفر نیستند** — چون `|10⟩` (با t=0) به `|11⟩` (با t=1) نگاشته می‌شود. نشتی داریم. ❌

## ۳. چرا این پرسشِ اصلیِ کامپایلر ماست؟

حالت گربه‌ای بعد از Cat-Ent را به یاد بیاورید
(نگاه کنید به [مفاهیم پایه](01-concepts.md)):

```
α · |0⟩_c |0⟩_comm  +  β · |1⟩_c |1⟩_comm
```

کیوبیت ارتباطی در QPU دوردست، **یک رونوشت از مقدار صفر-یا-یکِ `c`** را نگه داشته است.
این رونوشت، **تمام مکانیزم** کار است — دلیل اینکه یک CZ محلی در آن سوی شبکه
می‌تواند جایگزین یک CZ غیرمحلی شود، همین است.

حالا:

- گیتی اعمال کنیم که **روی `c` قطری است** → مقدار `c` تغییر نمی‌کند
  → **رونوشت هنوز معتبر است** → گروه زنده می‌ماند. ✅
- گیتی اعمال کنیم که **روی `c` قطری نیست** → مقدار `c` عوض شده
  → **رونوشت کهنه و غلط است** → محاسبه خراب می‌شود. ❌

> **«آیا گروه می‌شکند؟» و «آیا این گیت روی کنترلِ نگه‌داشته‌شده قطری است؟»
> دقیقاً یک پرسش واحد هستند.**

## ۴. صورت فشرده (مناسب برای کد)

یک بیان هم‌ارز وجود دارد که پیاده‌سازی‌اش بسیار ساده‌تر است:

> **`U` روی کیوبیت `q` قطری است ⟺ `U` با گیت `Z` روی `q` جابه‌جا می‌شود.**

یعنی `U · Z_q == Z_q · U`.

این منطقی است: `Z` همان گیتی است که برچسب‌گذاری ۰/۱ را «اندازه می‌گیرد»،
پس هر عملگری که با آن برچسب‌گذاری سازگار باشد، با `Z` جابه‌جا می‌شود.

---

## ۵. جدول مرجع برای پیاده‌سازی

| گیت | روی کدام کیوبیت‌هایش قطری است؟ |
|---|---|
| `z`, `rz`, `s`, `t`, `sdg`, `tdg`, `p` | تنها کیوبیتش |
| `cz` | **هر دو** کیوبیت |
| `cx` / `cnot` | فقط کنترل (`qubits[0]`) |
| `h`, `x`, `y`, `rx`, `ry`, `swap` | **هیچ‌کدام** |

---

## ۶. تمرین: این جدول را باور نکنید، بررسی‌اش کنید

یک اسکریپت آزمایشی بنویسید که برای هر گیت جدول بالا:

1. ماتریسش را بگیرد
   (`from qiskit.quantum_info import Operator` و سپس `Operator(gate).data`
   که یک آرایه‌ی NumPy می‌دهد)
2. ماتریس `Z` روی کیوبیت `q` را با همان ابعاد بسازد
3. بررسی کند که آیا `U @ Z_q` با `Z_q @ U` برابر است یا نه

اگر نتایج با جدول بالا خواند، حالا حق دارید به آن اعتماد کنید.

**دو نکته‌ی پایتونی:**
- در NumPy، عملگر `@` یعنی ضرب ماتریسی (نه `*` که درایه‌به‌درایه است).
- برای مقایسه‌ی ماتریس‌های اعشاری **هرگز** از `==` استفاده نکنید؛
  از `numpy.allclose(a, b)` استفاده کنید.
